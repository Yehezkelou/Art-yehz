## API exacte
### Python (`outils/vox.py`)
```
Modele(lx, ly, lz, nom="")                 # 1–256 par axe ; m[x, y, z] = i (0–32) ; m[x, y, z] → i ; m.lire(x, y, z) (0 hors grille)
m.boite(x0, y0, z0, x1, y1, z1, i)         # bornes incluses, dans n'importe quel ordre ; i = 0 creuse ; renvoie m
m.calques(lignes_par_y, legende, x0=0, y0=0, z0=0)   # calque n → y0+n ; ligne k → z0+k (la 1re = le fond) ; car. c → x0+c
                                           # calque = liste de chaînes ou texte multiligne ; « . » et espace = vide ;
                                           # caractère inconnu → ErreurVox ; renvoie m
m.miroir_x(nom=None) → Modele              # nouvelle grille, x → lx−1−x (l'original ne change pas)
m.copier(nom=None) → Modele ;  m.symetrie_x(depuis="gauche")   # (bonus : recopie une moitié sur l'autre, sur place)
m.voxels() → (x, y, z, i)… ; m.compter() ; m.couleurs() ; m.taille ; m.nom ; m.donnees (index x + lx·(y + ly·z))
ecrire_vox(chemin, modeles, palette=None)  # un Modele ou une liste ; version 150
lire_vox(chemin) → [Modele]                # noms relus ; accepte 150 et 200 ; index > 32 → ErreurVox
apercu(chemin_png, modele, vue="trois-quarts", taille=2)   # vues : trois-quarts (iso 2:1), face, dessus, cote
palette_magicavoxel(chemin_png)            # 256×1, pixel x = index x+1, au-delà de 32 : noir opaque
rampe(i) → {"dessus", "face", "cote", "dessous"} ; plus_sombre(i) ; RAMPES ; lire_palette() ; ecrire_png(…) ; lire_rgba(…)
CLI : python3 -I outils/vox.py info <f.vox> | apercu <f.vox> <png> [--vue] [--taille] [--modele n|nom] | palette <png>
```
Correspondance des axes avec MagicaVoxel (z en haut, face avant vue depuis −y) : `x_vox = x`,
`y_vox = lz − 1 − z`, `z_vox = y` ; SIZE = (lx, lz, ly). C'est une rotation, pas un miroir : la face avant
du script est la face avant dans MagicaVoxel.

Contenu du fichier : `VOX ` 150 → MAIN → (SIZE, XYZI) × n → nTRN 0 → nGRP 1 → (nTRN « _name » + « _t »,
nSHP) par modèle, posés côte à côte en x → LAYR 0 → RGBA.

### JS (`outils.voxel`, `outils/rendu3d/voxel.mjs`)
```
await outils.voxel.charger(chemin) → [Grille]   # chemin relatif à la racine du dépôt, ou "./…" = dossier de la scène
outils.voxel.maillage(grille, { rampe, contour = false, occlusion = true, centre = "bas", eclairage = "camera", taille = 1 }) → THREE.Mesh
    rampe     : surcharge { [index]: {dessus, face, cote, dessous} } ou fonction i → rampe ; défaut = table ci-dessous
    contour   : false | true (= 1) | 1 | 2  → LineSegments (arêtes vives fusionnées) en enfant « contour »,
                faces repoussées par polygonOffset
    occlusion : true (seuil 1) | false | 1–4 (seuil = nb de voisins pleins autour de la case devant la face)
    centre    : "bas" (milieu du dessous) | "milieu" | "coin" | [x, y, z]
    eclairage : "camera" (rôle de la face selon sa normale vue de la caméra, recalculé à chaque image
                dans onBeforeRender) | "fixe" (repère de l'objet)
    mesh.userData.voxel = { nom, lx, ly, lz, decalage, taille, faces, eclairage, aretes? } ;
    mesh.userData.ombrer(camera) pour forcer
outils.voxel.rig(parties, rigToml) → THREE.Group   # parties = { nom: Mesh } ; rigToml = texte TOML ou objet déjà lu
    groupe.poser(nomClip, t, { ips = 12, vitesse = 1, amplitude = 1, … }) ; groupe.repos()
    groupe.parties (pivots par nom), .roles (pivots par rôle), .mesures, .clips (copie modifiable), .definition
    structure : groupe (échelle) → « pose » (décalages d'ensemble des clips) → pivots → maillages
await outils.voxel.chargerRig(cheminToml, optionsMaillage) → THREE.Group   # lit le TOML et les .vox,
                                                   # maillage(…, centre "coin") par partie, puis rig()
outils.voxel.grille(lx, ly, lz, nom) → Grille (get, set, boite, compter) ; rampe(i) ; plusSombre(i) ; RAMPES ; CLIPS ;
lireToml(texte) ; lireVox(octets) ; url(chemin)
outils.texturePixel(chemin, { repeter = false }) → THREE.Texture   # NearestFilter min/mag, pas de mipmaps, sRGB ;
                                                   # la page attend la fin du chargement ; fichier absent → erreur du rendu
outils.halo(rayon, couleurs, { segments = 48, interieur = 0, camera = false }) → THREE.Group
    # anneaux pleins MeshBasic (couleurs du centre vers le bord, largeurs égales) dans le plan XY ;
    # camera : toujours face à la caméra
outils.pas12(t) = floor(12 t) / 12 ; outils.attendre() → Promise
```
Fonctions pures exportées par `voxel.mjs` (testées sous Node) : `faces(grille, {occlusion})` → quads gloutons,
`aretes(grille)`, `role(nx, ny, nz)`, `Grille`, `lireVox`, `lireToml`, `rampe`, `plusSombre`, `CLIPS`,
`fabriquerVoxel(THREE, {couleur, scene})`.

Rôle de chaque face, avec une lumière de face un peu en haut à gauche (même règle que les 7 scènes de
pixel-04) :

| Normale de la face | Rôle |
|---|---|
| y > 0,5 | dessus |
| y < −0,5 | dessous |
| z > 0,6 | face |
| tournée à gauche | cote |
| tournée à droite ou de dos | dessous |

## Format `.rig.toml` (ou `.json` de même structure)
Toutes les coordonnées sont en voxels, dans la grille commune du personnage.
```toml
nom = "chibi-demo"           # facultatif
echelle = 1                  # taille d'un voxel dans la scène (échelle du groupe)
sol = [5, 0, 4]              # facultatif : point qui devient l'origine du groupe (défaut : milieu du dessous de l'ensemble)
[parties.tete]
fichier = "voxel_demo.vox"   # relatif au .rig.toml (chargerRig seulement)
modele = "tete"              # nom ou numéro dans le fichier (défaut 0)
origine = [1, 9, 0]          # coin (0, 0, 0) de la partie dans la grille du perso (défaut [0, 0, 0])
pivot = [5, 9, 4]            # point de rotation
parent = "corps"             # absent = racine (sous « pose »)
role = "tete"                # facultatif, défaut = le nom
maillage = { contour = 2 }   # facultatif : options de maillage propres à la partie
[clips.balade]               # facultatif : clip dérivé (base = clip existant), options par défaut du clip
base = "marche"
vitesse = 0.6
amplitude = 0.7
```
- Erreurs signalées : partie sans maillage, parent inconnu, boucle de parents, vecteur mal formé, clip inconnu
  (avec la liste des clips disponibles).
- Le lecteur TOML côté Node gère les tables, les `[[tableaux]]`, les clés pointées ou entre guillemets, les
  chaînes simples, les nombres (avec `_`, en hexadécimal, `inf`), les booléens, les tableaux sur plusieurs lignes
  et les tables en ligne. Il ne gère ni les dates ni les chaînes multilignes. Un test vérifie qu'il donne le même
  résultat que `tomllib`.

Les 5 clips de base (12 i/s par défaut ; `u` = t cadencé × vitesse ; A = amplitude) :

| Clip | Mouvement |
|---|---|
| `idle` | cycle de 2 s : la tête dodeline et descend de 0,5 voxel, les bras se balancent de ±0,07 rad |
| `marche` | période de 0,7 s : jambes ±0,5 rad, bras ±0,4 rad en opposition, petite torsion du corps et de la tête ; « pose » descend de L·(1 − cos θ) pour garder les pieds au sol |
| `saut` | cycle de 1,2 s : élan (corps penché, bras en arrière), vol en parabole de 6 voxels (bras levés à 2,5 rad, jambes écartées), réception (hochement de tête) |
| `parle` | hochements à 3 Hz, inclinaison, geste du bras droit ; le rôle `bouche` est montré ou caché par 1/8 s (motif fixe) |
| `coucou` | bras droit levé (−2,4 rad en z) qui salue à 2,5 Hz, tête et corps qui balancent |

Gauche et droite sont ceux du personnage : `bras_d` est du côté −x (à gauche de l'écran en vue de face).
Pour ajouter un clip : `perso.clips.danse = (r, u, o) => { … }` (`r.roles`, `r.pose`, `r.mesures`), puis
`perso.poser("danse", t)`.

## Table de rampes par défaut (identique en Python et en JS, vérifiée par un test)
Les rampes, de la plus sombre à la plus claire : gris **1–8 en une seule rampe continue**, puis 9–12, 13–16,
17–20, 21–24, 25–28 et 29–32. La couleur du voxel reste celle de la face.
- **Index qui a un voisin plus clair** : dessus = +1, cote = −1, dessous = −2.
- **Index le plus clair de sa rampe** : dessus = −1, cote = −2, dessous = −3, pour que le dessus reste distinct
  de la face. C'est le choix des agents pour la crème `[5, 6, 8, 7]`.
- **Bornes** : on ne sort jamais de la rampe ; si le cran manque, la couleur la plus sombre se répète.
- **Occlusion** : un cran plus sombre dans la même rampe.

| i | dessus | face | cote | dessous |
|---|---|---|---|---|
| 1 | 2 | 1 | 1 | 1 |
| 2 | 3 | 2 | 1 | 1 |
| 3 | 4 | 3 | 2 | 1 |
| 4 | 5 | 4 | 3 | 2 |
| 5 | 6 | 5 | 4 | 3 |
| 6 | 7 | 6 | 5 | 4 |
| 7 | 8 | 7 | 6 | 5 |
| 8 | 7 | 8 | 6 | 5 |
| 9 / 13 / 17 / 21 / 25 / 29 | +1 | i | i | i |
| 10 / 14 / 18 / 22 / 26 / 30 | +1 | i | −1 | −1 |
| 11 / 15 / 19 / 23 / 27 / 31 | +1 | i | −1 | −2 |
| 12 / 16 / 20 / 24 / 28 / 32 | −1 | i | −2 | −3 |

Exemples : or 19 → 20 / 19 / 18 / 17, exactement la rampe des scènes `equation` et `fameux` ; crème 8 →
7 / 8 / 6 / 5, comme les agents.

Écart assumé : le contrat parle de « rampe de 4 ». Pour les 8 gris, j'ai pris une seule rampe continue, parce
que les agents la traversent déjà (`ecrans` [3, 4, 5], `circuit` 5 → 4) et que la couper en 1–4 et 5–8 aplatirait
le 4 et le 5. Pour revenir à deux rampes de 4, il suffit de modifier `RAMPES`, à deux endroits (`vox.py` et
`voxel.mjs`, que le test garde synchrones).

## Incertain / limites
- **MagicaVoxel non testé ici** (pas installé sur cette machine). Le fichier suit la spécification
  (ephtracy/voxel-model, version 150 avec nTRN/nGRP/nSHP/LAYR) et nos tests relisent tous les chunks. À confirmer
  en ouvrant `outils/rendu3d/exemples/voxel_demo.vox` dans MagicaVoxel (6 modèles côte à côte, noms visibles)
  après avoir chargé la palette PNG.
- **Seuil d'occlusion** : 1 par défaut, donc toute face qui touche un mur perpendiculaire est assombrie (bande de
  contact). Si c'est trop marqué sur les dioramas, passer `occlusion: 2` (vrais coins seulement).
- **Contour** : ce sont des arêtes vives en traits de 1 px (`LineSegments`), pas une silhouette. Sur des
  voxels de 3 px à l'écran, ça peut charger l'image ; c'est pourquoi le contour est désactivé par défaut.
- **Rôles recalculés selon la caméra** : la couleur d'une face bascule d'un coup quand elle tourne (style voulu,
  comme dans les 7 scènes). En perspective, une face un peu de biais au bord de l'écran peut prendre le rôle voisin.
- **Clips** : angles réglés à l'œil sur le chibi de démo. Pour d'autres proportions, jouer sur `amplitude`, ou
  ajouter un clip propre au rig.
- **Halo `camera: true`** : il tourne dans `onBeforeRender`. Il est donc correct pour la caméra qui dessine,
  mais un halo vu par deux caméras dans la même image prendrait l'orientation de la dernière.
- **Fichiers de démo dans `exemples/`** : ils sont générés et je ne les ai pas mis dans `.gitignore` (fichier hors
  mission). Les tests, eux, régénèrent la démo dans un dossier temporaire.
- **Références à mettre à jour** (hors des fichiers autorisés) : `CLAUDE.md` (liste des outils) et le journal
  n° 41. `outils.voxel` remplace l'ombrage recopié dans les scènes ; les 7 scènes de pixel-04 restent telles
  quelles.
