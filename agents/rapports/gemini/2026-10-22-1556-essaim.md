## 1. Résumé de la Méthode de `@cassandre.rollet` (en 8 lignes, reformulé)

*Source analysée : [guide.txt](file:///C:/Users/HP/Documents/yehz/Art-yehz/a-trier/guide-opus/guide.txt#L1-L859) (« Monter tes vidéos en motion design avec Claude », v1.0, oct. 2026, par `@cassandre.rollet`).*

1. **Principe** : Considérer l'habillage vidéo comme une page web animée générée en français par Claude Code (Opus), puis capturée en `.mp4` via Chrome Headless et FFmpeg ([guide.txt](file:///C:/Users/HP/Documents/yehz/Art-yehz/a-trier/guide-opus/guide.txt#L32-L34), [guide.txt](file:///C:/Users/HP/Documents/yehz/Art-yehz/a-trier/guide-opus/guide.txt#L75-L87)).
2. **Séparation en 2 skills** : `video-use` prépare le rush face caméra (suppression des silences/hésitations via transcription ElevenLabs, sous-titres simples), puis `Hyperframes` génère le motion design HTML/CSS (titres, texte derrière le sujet détouré, widgets, graphiques, transitions) ([guide.txt](file:///C:/Users/HP/Documents/yehz/Art-yehz/a-trier/guide-opus/guide.txt#L131-L173)).
3. **Workflow en 4 étapes** : (1) Dérucher avant d'animer ; (2) Valider un storyboard minuté limité à 3–4 moments forts ; (3) Coder la timeline HTML (`data-start`, `data-duration`) et prévisualiser ; (4) Corriger en ≤ 3 retouches sur planche contact avant l'export final ([guide.txt](file:///C:/Users/HP/Documents/yehz/Art-yehz/a-trier/guide-opus/guide.txt#L184-L263), [guide.txt](file:///C:/Users/HP/Documents/yehz/Art-yehz/a-trier/guide-opus/guide.txt#L569-L571)).
4. **Grammaire de prompt (5 ingrédients)** : Spécifier systématiquement *Quoi + Quand (mot déclencheur) + Où + Style + Mouvement*, précédé d'un « prompt maître » fixant la palette, les 2 polices et les interdits ([guide.txt](file:///C:/Users/HP/Documents/yehz/Art-yehz/a-trier/guide-opus/guide.txt#L280-L315), [guide.txt](file:///C:/Users/HP/Documents/yehz/Art-yehz/a-trier/guide-opus/guide.txt#L636-L650)).
5. **Rétention (« Montrer au lieu de dire »)** : Concentrer l'impact sur le hook (`0–7 s`) et illustrer chaque preuve, durée ou statistique par 3 à 5 séquences plein écran (1–5 s) aux textures variées, soutenues par des bruitages discrets mixés à `−8 dB` sous la voix pour un master à `−14 LUFS` ([guide.txt](file:///C:/Users/HP/Documents/yehz/Art-yehz/a-trier/guide-opus/guide.txt#L476-L525), [guide.txt](file:///C:/Users/HP/Documents/yehz/Art-yehz/a-trier/guide-opus/guide.txt#L612-L618)).

### 2.1 `heygen-com/hyperframes`
- **Dépôt & Fichiers de preuve** :
  - Dépôt : `https://github.com/heygen-com/hyperframes`
  - Licence : `https://github.com/heygen-com/hyperframes/blob/main/LICENSE` (**Apache-2.0**)
  - Crédits et exclusions : `https://github.com/heygen-com/hyperframes/blob/main/CREDITS.md`
  - Monorepo workspace : `https://github.com/heygen-com/hyperframes/blob/main/package.json` (`packages/cli`, `packages/core`, `packages/parsers`, `packages/engine`, `packages/producer`, `packages/studio`).
- **Licence réelle** : **Apache License 2.0** (permissive, autorise l'usage commercial). `CREDITS.md` exclut toutefois les marques/logos HeyGen et signale que certains assets/polices tiers embarqués gardent leur propre licence.
- **Dépendances & Architecture** :
  - Exige **Node.js `>=22`**, **FFmpeg/FFprobe** dans le `$PATH`, et télécharge **`chrome-headless-shell`** piloté via **`puppeteer-core`** et `@puppeteer/browsers` (`packages/engine/package.json`).
  - Capture chaque frame de manière déterministe via le protocole CDP `HeadlessExperimental.beginFrame` en avançant une horloge virtuelle (`window.__hf`), puis pipe les buffers d'images vers FFmpeg (`@hyperframes/producer`).
  - La skill optionnelle `/media-use` (`skills/media-use/scripts/resolve.mjs`) orchestre transcription (Whisper/Parakeet), TTS (Kokoro local ou cloud) et détourage (`npx hyperframes remove-background` via `rembg` / BiRefNet / SAM / MediaPipe en local).
- **Ce qui part sur le réseau (ALERTE TÉLÉMÉTRIE)** :
  - **Télémétrie PostHog ACTIVE PAR DÉFAUT** (`packages/studio/src/telemetry/events.ts`, commande `npx hyperframes telemetry` et sous-commande `npx hyperframes events` invoquée par les skills) : envoie les commandes CLI exécutées, métriques de rendu, étapes de funnel des skills et erreurs, en plus du check de version npm. Désactivation via `HYPERFRAMES_NO_TELEMETRY=1`, `DO_NOT_TRACK=1` ou `npx hyperframes telemetry disable` (`~/.hyperframes/config.json`).
  - **Clés API cloud** : non requises pour un rendu HTML local hors-ligne, mais requises dès qu'on appelle HeyGen Cloud (`HEYGEN_API_KEY` via `npx hyperframes auth`) ou les connecteurs cloud de `/media-use` (`GEMINI_API_KEY`, `OPENAI_API_KEY`, `ELEVENLABS_API_KEY`, `FAL_KEY`, `REPLICATE_API_TOKEN`).
- **Compatibilité Windows / WSL2** :
  - **Sous WSL2** : `chrome-headless-shell` échoue fréquemment à accéder au GPU hôte (`[hyperframes] WSL: the GPU check found no hardware GPU, so this render uses software WebGL`) et bascule sur le rasterizer logiciel **SwiftShader** très lent — exactement le même piège que `llvmpipe` déjà subi sur l'usine ([ce-qui-m-a-gene.md](file:///C:/Users/HP/Documents/yehz/Art-yehz/ce-qui-m-a-gene.md#L19), entrée #10b).
  - **Sous Windows natif** : bugs documentés sur `chrome-headless-shell.exe` (absence de `dxil.dll`/`dxcompiler.dll` cassant WebGPU, et fenêtre de console parasite avec `--low-memory-mode`).
